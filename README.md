# put.gd-site

The landing page for [put.gd desktop](https://github.com/patrick-hudson/put.gd-desktop), served at
<https://app.put.gd/> and as the root page of <https://put.gd/>. Plain HTML, CSS and a little
JavaScript; no build step.

## Layout

| Path | What it is |
| --- | --- |
| `public/index.html` | The page. Everything it references lives under `public/_site/`. |
| `public/_site/site.css`, `site.js` | Styles; `site.js` only adds the copy buttons. The page works without JavaScript. |
| `public/_site/season.js` and the `logo-`, `favicon-`, `art-`, `leaves-` and `sprig-` SVGs | The seasonal theme; see [Seasons](#seasons). |
| `public/_site/tokens.css` | The app's colours, generated by `tools/tokens.py` from `Theme.cpp` at a release tag. Do not edit. |
| `public/_site/fonts/` | Latin subsets of the IBM Plex files the app bundles, written by `tools/fonts.sh`. |
| `public/_site/releases.json` | Generated by `tools/releases.py` at deploy time; not committed. Internal to the page. |
| `public/update/v1/stable.json`, `nightly.json` | The update feed the app reads, served at `https://app.put.gd/update/v1/<channel>.json` as `application/json` with `max-age=300`. Generated by `tools/releases.py` at deploy time; not committed. Contract v1 is defined in [put.gd-desktop #293](https://github.com/patrick-hudson/put.gd-desktop/issues/293): `release` is `null` while a channel has none, `sha256` comes from the release's `SHA256SUMS` and is omitted when that can't be read, and the AppImage entry has `zsync` only once the release ships an `.AppImage.zsync`. |
| `public/_site/shots/` | Real windows from a released build on a lab desktop, dark and light, AVIF and WebP, with `shots.json` (build, desktop, demo-media credits). Written by `tools/shots/`; see [its README](tools/shots/README.md). |
| `tools/render.py` | Fills the release details into `index.html` between `<!--r:KEY-->` markers, checks every `/_site/` reference, and at deploy time stamps asset URLs with `?v=<sha>`. Download links follow the stable channel once one exists, nightly until then. |
| `tools/releases.py` | Builds `releases.json` and the update feeds from the GitHub releases: `stable` is the newest non-prerelease, `nightly` the newest nightly prerelease (`vYY.MDD.N-nightly`, or `v0.Y.Z-nightly.N` before [put.gd-desktop #373](https://github.com/patrick-hudson/put.gd-desktop/issues/373)). Refuses to write a feed that breaks contract v1. |
| `tools/test_season.py`, `season.test.js` | Offline tests for the season dates, midnight rescheduling and clean-up. Needs Node. |
| `tools/season_review.py` | Browser checks and screenshots of every season; see [Seasons](#seasons). |
| `tools/test_releases.py`, `test_site.py` | Offline tests for the feeds (including the empty stable channel), the permalinks, the renderer and the token generator; the deploy runs them first. |
| `tools/update-kvs.py` | Writes the `/dl/<channel>/<package>` redirect targets into the CloudFront KeyValueStore. |
| `cloudfront/download-redirect.js` | CloudFront Function on app.put.gd: `/` to `index.html`, `/dl/...` to the current asset. Everything else, `/update/*` included, goes to the site bucket unchanged. |
| `.github/workflows/deploy.yml` | Publishes to S3, refreshes the permalinks, invalidates CloudFront. |
| `infra/` | Terraform for the distributions, the buckets, the role and DNS, including `demo.put.gd`, the demo destination the screenshots upload to (`infra/demo.tf`; objects expire after 30 days). On put.gd only `/` (default root object) and `/_site/*` reach the site bucket; every upload key keeps going to the uploads bucket. |

## Working on it

```bash
python3 tools/releases.py            # writes public/_site/releases.json and public/update/v1/*.json
python3 tools/render.py              # fills the release details into public/index.html
python3 -m unittest discover -s tools
python3 -m http.server 4411 --directory public
```

Then open <http://127.0.0.1:4411/>. Rendering is idempotent and keeps its markers, so a rendered
`index.html` can be committed as is.

When the app's look changes, refresh the page from the release the screenshots come from:

```bash
python3 tools/tokens.py --tag vYY.MDD.N-nightly   # colours
tools/fonts.sh vYY.MDD.N-nightly                  # fonts
python3 tools/shots/capture.py                    # screenshots; see tools/shots/README.md
uv run --with pillow python tools/og.py           # link preview from the desktop shot
```

The app's internal design codename stays off the site; the deploy fails if any file names it
(the word is in the `SITE_CODENAME_GUARD` repository variable).

## Seasons

The site themes itself from the visitor's local date, every year, with nothing to deploy or
maintain: the turkey and harvest colours for all of November, the tree, lights and snow for all of
December, and the ordinary page otherwise. `season.js` decides on load, again at each local
midnight, and when a tab comes back (`pageshow`, `focus`, `visibilitychange`). Without JavaScript the
ordinary page stays. The screenshots are real and are never themed. In both months the logo link's
hover text, and a tip on keyboard focus, say "put.gd - Happy Holidays!"; its name stays the same.

Seasonal colours and artwork URLs live in `site.css` as variables on `html[data-season]`, so
`render.py` checks and stamps them like any other asset and ordinary visitors never download them.

To look at a season without changing the clock, open the local server with
`?season=november`, `?season=december` or `?season=ordinary`. The parameter only works on
`localhost`, `127.0.0.1` and `[::1]`. To check all of them, in both colour schemes and at every
size, including layout, clean-up at midnight and reduced motion:

```bash
uv run --with playwright python tools/season_review.py --out /tmp/season-review
```

## Deploying

Every push to `main` deploys. The workflow also runs when put.gd-desktop publishes a release
(`repository_dispatch` with type `release-published`), every six hours as a backstop, and by hand
from the Actions tab. It assumes an AWS role through GitHub OIDC; no long-lived keys are stored. The repository uses
GitHub's immutable OIDC subject, so the role trusts `repo:patrick-hudson@5728403/put.gd-site@1426482917:environment:production`
(see `infra/iam.tf`).

The AWS side is described in `infra/` (Terraform, state in the `putgd-site-terraform-state` bucket):
`terraform -chdir=infra plan` should be clean; `apply` after changing anything there.

Repository variables: `AWS_DEPLOY_ROLE_ARN`, `SITE_BUCKET`, `CLOUDFRONT_DISTRIBUTION_IDS`
(space separated), `CLOUDFRONT_KVS_ARN`, `SITE_CODENAME_GUARD`. The `production` environment gates the deploy job.

| `https://app.put.gd/dl/stable/ubuntu24.04` | current stable DEB for Ubuntu 24.04 and Mint 22 |
| `https://app.put.gd/dl/stable/ubuntu26.04` | current stable DEB for Ubuntu 26.04 |

| `https://app.put.gd/dl/stable/appimage` | current stable AppImage |
| `https://app.put.gd/dl/stable/appimage.zsync` | that AppImage's `.zsync`, for AppImageUpdate, Gear Lever and put.gd's own updater, served from the package signer's bucket once the signer has mirrored the image it names; 404 until then |
| `https://app.put.gd/dl/stable/checksums` | that release's `SHA256SUMS` |
| `https://app.put.gd/dl/stable` | that release's page |

Replace `stable` with `nightly` for the newest nightly. A channel with no release answers 404.

## Update feed

| URL | What it is |
| --- | --- |
| `https://app.put.gd/update/v1/stable.json` | the current stable release for the in-app update check; `"release": null` until the first stable ships |
| `https://app.put.gd/update/v1/nightly.json` | the newest nightly |

Each deploy (every release publish, every six hours, every push) rewrites both. The app compares
versions locally; see [put.gd-desktop #293](https://github.com/patrick-hudson/put.gd-desktop/issues/293)
for the contract and the client's rules.
