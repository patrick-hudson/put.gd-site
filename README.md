# put.gd-site

The landing page for [put.gd desktop](https://github.com/patrick-hudson/put.gd-desktop), served at
<https://app.put.gd/> and as the root page of <https://put.gd/>. Plain HTML, CSS and Microsoft® TypeScript.

## Layout

| Path | What it is |
| --- | --- |
| `index.html` | The page shell. Vite bundles the app into `dist/_site/enterprise/`, because on put.gd only `/` and `/_site/*` reach the site bucket. |
| `src/main/typescript/com/putgd/enterprise/` | The application. See [Architecture](#architecture). |
| `src/main/resources/applicationContext.xml` | Bean definitions: which implementation backs each interface, and every tunable number and string. |
| `public/` | Copied into `dist/` unchanged: `404.html`, `robots.txt`, `sitemap.xml` and everything under `_site/`. |
| `public/_site/site.css` | Styles and the hero animation choreography. |
| `public/_site/releases.json` | Generated by `tools/releases.py` at deploy time; not committed. Internal to the page. |
| `public/update/v1/stable.json`, `nightly.json` | The update feed the app reads, served at `https://app.put.gd/update/v1/<channel>.json` as `application/json` with `max-age=300`. Generated by `tools/releases.py` at deploy time; not committed. Contract v1 is defined in [put.gd-desktop #293](https://github.com/patrick-hudson/put.gd-desktop/issues/293): `release` is `null` while a channel has none, `sha256` comes from the release's `SHA256SUMS` and is omitted when that can't be read, and the AppImage entry has `zsync` only once the release ships an `.AppImage.zsync`. |
| `public/_site/shots/` | Real windows from the current nightly on the lab desktops, as WebP. |
| `tools/releases.py` | Builds `releases.json` and the update feeds from the GitHub releases: `stable` is the newest non-prerelease, `nightly` the newest nightly prerelease (`vYY.MDD.N-nightly`, or `v0.Y.Z-nightly.N` before [put.gd-desktop #373](https://github.com/patrick-hudson/put.gd-desktop/issues/373)). Refuses to write a feed that breaks contract v1. |
| `tools/test_releases.py` | Offline tests for the feeds (including the empty stable channel) and the permalinks; the deploy runs them first. |
| `tools/update-kvs.py` | Writes the `/dl/<channel>/<package>` redirect targets into the CloudFront KeyValueStore. |
| `cloudfront/download-redirect.js` | CloudFront Function on app.put.gd: `/` to `index.html`, `/dl/...` to the current asset. Everything else, `/update/*` included, goes to the site bucket unchanged. |
| `.github/workflows/deploy.yml` | Builds `dist/`, publishes it to S3, refreshes the permalinks, invalidates CloudFront. |
| `infra/` | Terraform for both distributions, the bucket, the role and DNS. On put.gd only `/` (default root object) and `/_site/*` reach the site bucket; every upload key keeps going to the uploads bucket. |

## Working on it

Needs Node 22 or newer and Python 3.

```bash
npm install
python3 tools/releases.py            # optional: writes public/_site/releases.json so the install table fills in
python3 -m unittest discover -s tools
npm run dev                          # http://localhost:4411/
npm test                             # Vitest, or npm run test:watch
npm run build                        # type-checks, then writes dist/
```

The hero animation is pure CSS on a 9 s loop (`--T` in `site.css`); the selection geometry is in
`cqw` units so it tracks the terminal text at any width.

## Architecture

`Main.tsx` imports `ComponentScan.ts`, which imports every class under `impl/` so its
`@EnterpriseBean("com.putgd.enterprise.impl...")` decorator registers it with the `BeanClassRegistry`.
`XmlBeanDefinitionReaderImpl` parses `applicationContext.xml`, and
`DefaultSingletonEnterpriseApplicationContextImpl` instantiates beans lazily as singletons, resolving
`ref`, `value` and `<list>` constructor arguments and refusing circular references. Components get
beans with `useEnterpriseBean<T>("beanId")`.

| Package | What lives there |
| --- | --- |
| `framework/ioc/` | The container, the XML reader, the React bridge, and its exceptions. |
| `interfaces/` | One interface per concern: strategies, factories, providers, formatters, converters, visitors, repositories, services, schedulers, state machines, string returners. |
| `impl/` | One implementation of each, registered as a bean. Page copy lives in `impl/repositories/`. |
| `model/` | Enums, view models and DTOs. |
| `presentation/hooks/` | Selection readout, scroll-reveal fallback, console typewriter, copy buttons, install table. |
| `presentation/components/` | Pages, layout, the five sections (ordered by `sectionOrderingStrategy` in the XML), primitives. |

To add a bean: write the interface, write the `Impl` with `@EnterpriseBean`, add its import to
`ComponentScan.ts`, and define it in `applicationContext.xml`.
A missing import fails at startup with `NoSuchBeanClassException`.

## Tests

`src/test/typescript/com/putgd/enterprise/` mirrors the main tree and runs in jsdom.
`support/FakeBrowserEnvironment.ts` stands in for the browser APIs jsdom lacks (reduced motion,
`CSS.supports`, `IntersectionObserver`, `getAnimations`, the clipboard, `fetch`) and resets before
each test. `presentation/LegacyPageParityTest` renders the app and compares it, element by element,
against the pre-React page kept in `src/test/resources/fixtures/legacy-index.html`. Change both if
the page changes on purpose. Both workflows run `npm test` before building.

## Deploying

Every push to `main` deploys. The workflow also runs when put.gd-desktop publishes a release
(`repository_dispatch` with type `release-published`), every six hours as a backstop, and by hand
from the Actions tab. It assumes an AWS role through GitHub OIDC; no long-lived keys are stored. The repository uses
GitHub's immutable OIDC subject, so the role trusts `repo:patrick-hudson@5728403/put.gd-site@1426482917:environment:production`
(see `infra/iam.tf`).

The AWS side is described in `infra/` (Terraform, state in the `putgd-site-terraform-state` bucket):
`terraform -chdir=infra plan` should be clean; `apply` after changing anything there.

Repository variables: `AWS_DEPLOY_ROLE_ARN`, `SITE_BUCKET`, `CLOUDFRONT_DISTRIBUTION_IDS`
(space separated), `CLOUDFRONT_KVS_ARN`. The `production` environment gates the deploy job.

## Update feed

| URL | What it is |
| --- | --- |
| `https://app.put.gd/update/v1/stable.json` | the current stable release for the in-app update check; `"release": null` until the first stable ships |
| `https://app.put.gd/update/v1/nightly.json` | the newest nightly |

Each deploy (every release publish, every six hours, every push) rewrites both. The app compares
versions locally; see [put.gd-desktop #293](https://github.com/patrick-hudson/put.gd-desktop/issues/293)
for the contract and the client's rules.
